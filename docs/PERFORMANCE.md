# 성능 측정과 최적화

## 1. 가상 스크롤 · 메모이제이션 측정

### 측정 방법

- 데이터: 카카오 API에서 "자바" 검색 결과 500권(50개씩 10페이지, 중복 제거)
- 비교 대상
  - **가상 스크롤**: 실제 사용 중인 `BookList` (`useWindowVirtualizer`)
  - **일반 목록 + memo**: 500개를 모두 렌더링, 행은 `memo`로 감싼 `BookListRow`
  - **일반 목록, memo 없음**: 500개를 모두 렌더링, 행을 `memo` 없이 렌더링
- 도구: React `<Profiler>`의 `actualDuration` 합계, `document.querySelectorAll('*').length`
- 환경: 개발 모드(`pnpm dev`), Chromium, 뷰포트 1280×1000, 모드마다 3회 측정
- 측정용 페이지는 저장소에 포함하지 않았습니다. 개발 모드라 절대값은 프로덕션보다 크며, **모드 간 상대 비교**로 봐 주세요.

### 결과 (3회 평균)

| 항목                            | 가상 스크롤 | 일반 목록 + memo | 일반 목록 (memo 없음) |
| ------------------------------- | ----------: | ---------------: | --------------------: |
| 첫 렌더링 커밋 시간 합계        |  **25.4ms** |          193.2ms |                     – |
| 렌더링된 아이템 수              |      **14** |              500 |                   500 |
| DOM 노드 수                     |     **566** |            7,598 |                 7,598 |
| 아이템 하나 펼치기 커밋 시간    |       8.4ms |           11.5ms |            **50.2ms** |
| 하트 하나 누르기 커밋 시간      |       0.8ms |            1.4ms |                 1.2ms |
| 스크롤 20회(1000px씩) 커밋 합계 |     169.2ms |          **0ms** |                     – |

### 해석

- **첫 렌더링 약 7.6배 단축, DOM 노드 약 93% 감소.** 화면 근처 14개만 그리므로 목록이 길어져도 첫 렌더링 비용이 거의 일정합니다.
- **memo의 효과는 "펼치기"에서 드러납니다.** 펼침 상태(`Set`)가 바뀌면 목록 전체가 다시 렌더링되는데, `memo`가 없으면 500개 행이 모두 다시 그려져 50ms가 걸립니다. `memo`가 있으면 props가 바뀐 행 하나만 다시 그려집니다.
- **하트는 목록과 무관하게 빠릅니다.** `FavoriteToggle` / `FavoriteIndicator`가 해당 책의 찜 여부만 selector로 구독해, 하트 하나를 눌러도 그 하트만 리렌더됩니다.
- **트레이드오프: 가상 스크롤은 스크롤할 때 렌더링 비용이 생깁니다.** 새로 보이는 행을 마운트하느라 스크롤 한 번(1000px)에 약 8ms(개발 모드)가 듭니다. 한 프레임(16ms) 안이라 체감 끊김은 없었고, 일반 목록은 대신 첫 렌더링에 193ms와 7,598개의 DOM을 계속 들고 있어야 합니다. 무한 스크롤로 목록이 계속 길어지는 화면이라 가상 스크롤을 택했습니다.

## 2. 그 밖의 최적화

| 항목             | 내용                                                                                                                                                                      |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 요청 수          | Enter로만 검색(디바운스 불필요), 쿼리 키 캐시 + `staleTime` 5분, 조건이 바뀌면 이전 요청 취소(`AbortSignal`)                                                              |
| 다음 페이지 요청 | overscan이 아니라 **실제로 보이는 범위**의 끝에서 3번째가 보일 때 요청 (처음에는 첫 화면에서 바로 2페이지를 요청하던 문제를 측정 중 발견해 수정)                          |
| 이미지           | `loading="lazy"`, `decoding="async"`, 크기 고정으로 레이아웃 밀림 방지                                                                                                    |
| 펼친 표지 이미지 | 카카오 썸네일은 120×174만 제공되어(다른 크기 요청 시 403) 210×280 표지에서 흐려짐 → 썸네일 URL의 원본(`fname`, 약 458×658)을 https로 사용, 실패 시 썸네일 → 대체 일러스트 |
| 연결 미리 열기   | `dapi.kakao.com`, `search1.kakaocdn.net` preconnect, `t1.daumcdn.net` dns-prefetch                                                                                        |
| 코드 분할        | 찜 페이지를 react-router `lazy`로 분리                                                                                                                                    |
| 개발 도구        | React Query Devtools는 프로덕션 번들에 포함되지 않음(소스맵으로 확인)                                                                                                     |

## 3. 번들

| 파일                 |   크기 |   gzip |
| -------------------- | -----: | -----: |
| `index-*.js`         | 499 kB | 159 kB |
| `FavoritesPage-*.js` | 0.8 kB | 0.5 kB |
| `index-*.css`        | 276 kB |  89 kB |

- JS의 대부분은 react-dom, react-router, axios, TanStack Query입니다.
- CSS의 대부분은 Noto Sans KR의 `@font-face` 선언(굵기당 124개)입니다. 한국어 폰트를 `unicode-range`로 잘게 나눠, **페이지에 실제로 쓰인 글자 조각만** 내려받기 위한 것입니다. 한 파일짜리 한국어 폰트(굵기당 542 kB × 3)로 바꾸면 CSS는 줄지만 폰트 다운로드가 훨씬 커져, 현재 방식을 유지했습니다.
